# Invest Care Limited — Corporate Website

Multipage marketing site for **Invest Care Limited**, a Kathmandu-based
investment holding company raising promoter capital ahead of a planned public
offering.

Built with **Next.js 15 (App Router, JSX)**, **Tailwind CSS**, **Framer Motion**
and **react-three-fiber / three.js**.

---

## Getting started

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production build
npm start        # serve the production build
npm run lint
```

Node 18.18+ is required (developed on Node 22).

## The landing page

`src/app/page.jsx` composes twelve sections, each self-contained in
`src/components/sections/`:

| # | Section | What makes it move |
| --- | --- | --- |
| 1 | `hero/` | WebGL scene, pointer spotlight, line-masked headline, magnetic CTAs, live promoter-round panel with progress bar, counting metrics band, scroll-linked parallax fade |
| 2 | `TickerBand` | Two counter-scrolling CSS marquees (sectors / company facts), paused on hover |
| 3 | `BentoOverview` | Asymmetric bento grid; cursor-tracking spotlight cards; word-by-word heading reveal |
| 4 | `StatsBand` | Four figures counting up on entry over a drifting aurora, with a line that draws across the band |
| 5 | `CapitalJourney` | Pinned left panel with a rotating step dial, driven by whichever step is in view on the right |
| 6 | `SectorAllocation` | Animated SVG donut linked to a hoverable sector list |
| 7 | `PortfolioShowcase` | Pinned horizontal scroll on `lg+`, scroll-snap carousel below it |
| 8 | `GlobalStrip` | Berkshire / Blackstone benchmarks as spotlight cards |
| 9 | `LeadershipStrip` | Staggered board portraits |
| 10 | `WhyInvest` | Five numbered spotlight cards on an aurora-lit dark band |
| 11 | `QuoteParallax` | Board quote brightening word by word over a parallax marquee |
| 12 | `CallToAction` | Closing conversion band |

**Performance and correctness notes**

- The WebGL scene is the only heavy dependency and it is code-split, client-only
  and behind a gradient fallback — the home route's first-load JS is ~183 kB.
- `PortfolioShowcase` measures its own track width with a `ResizeObserver`
  rather than hard-coding a translate percentage, so the rail lands exactly on
  the last card at every breakpoint. Its `useScroll` offset (`end end`) is
  chosen so progress `1` coincides with the moment the sticky panel releases.
- Marquees, aurora blobs and float loops are pure CSS keyframes — no
  per-frame JS.
- The custom cursor, magnetic hover and 3D pointer parallax all no-op on coarse
  pointers and under reduced motion.

## Project structure

```
src/
├── app/                  # App Router pages, layout, template, metadata routes
│   ├── layout.jsx        # fonts, metadata, preloader, nav, footer
│   ├── template.jsx      # route-change fade (re-mounts per navigation)
│   ├── globals.css       # Tailwind layers + component/utility classes
│   └── <route>/page.jsx
├── components/
│   ├── layout/           # Navbar, Footer, Logo, Preloader, ScrollProgress,
│   │                     #   CustomCursor
│   ├── sections/         # Page sections — each is self-contained and reusable
│   │   └── hero/         # The fold, split into content + backdrop + intro +
│   │                     #   raise panel + metrics band
│   ├── three/            # WebGL hero scene (+ lazy, client-only wrapper)
│   └── ui/               # Primitives: Section, SectionHeading, Button, Reveal,
│                         #   MediaFrame, AllocationDonut, Counter, PageHero,
│                         #   Aurora, Marquee, TextReveal, Magnetic, SpotlightCard
├── data/                 # All copy and figures from the business profile
├── theme/                # Design system: tokens, semantic surfaces, provider
└── lib/                  # Motion variants, className + contrast helpers
```

**Content lives in `src/data/`, not in components.** Updating a figure, a
director bio or a portfolio metric means editing one object — no JSX changes.

## Images

No photography ships with the repo. Every image slot renders a labelled
placeholder stating the expected path and dimensions, so layout is already
final and nothing shifts when real assets land.

To add a real image:

1. Save the file under `public/images/…` (see
   [`public/images/README.md`](public/images/README.md) for the full list of
   filenames and sizes).
2. In `src/data/portfolio.js` or `src/data/board.js`, replace `image: null` with
   the path shown in the adjacent comment.
3. For the editorial slots, set `src` on the `<MediaFrame>` in
   `src/components/sections/BentoOverview.jsx`, `src/app/about/page.jsx` and
   `src/app/contact/page.jsx` (each has a comment marking the intended path).

`MediaFrame` takes `tone="dark"` for slots that sit on dark cards, so the
placeholder never glows white against a forest background.

`MediaFrame` also falls back to the placeholder if a configured file 404s, so a
missing asset can never break a page.

The logo is currently drawn inline as SVG in
`src/components/layout/Logo.jsx`; swap `LogoMark` for a `next/image` pointing at
`public/images/brand/logo.svg` once the official file is available.

## Contact form

`src/components/sections/ContactForm.jsx` has **no mail backend**. Rather than
silently discarding enquiries, it composes a pre-filled message and hands it to
the visitor's own mail client via `mailto:`.

To move to server-side delivery, replace `handleSubmit` with a `POST` to a route
handler (`src/app/api/contact/route.js`) backed by Resend, SendGrid or SMTP.

## Design system

`src/theme/` is the single source of truth, in three layers:

| Layer | File | Contains |
| --- | --- | --- |
| Tokens | `theme/tokens.cjs` | Raw values: colour ramps, fonts, tracking, shadows, motion curves/durations, layout metrics. CommonJS so `tailwind.config.js` can `require()` it — Tailwind and the app are generated from the same object |
| Semantics | `theme/theme.js` | What values are *for*: `surfaces` (tone → background + heading/body/muted foregrounds), `button` variants and sizes, `scene` colours for the WebGL hero, `brand` |
| Runtime | `theme/ThemeProvider.jsx` | `useTheme()` — the theme plus live `prefersReducedMotion` / `hasFinePointer` flags, resolved once instead of in every component. Also applies framer-motion's `reducedMotion="user"` |

| Token | Value | Use |
| --- | --- | --- |
| `forest-950 … forest-50` | `#051a11` → `#f0f7f2` | Primary brand green |
| `gold-500` | `#c9a227` | Accent — figures, eyebrows, primary CTA on dark |
| `cream` | `#fbfaf6` | Page background |
| `font-display` | Fraunces | Headings |
| `font-sans` | Inter | Body |

Rules of thumb:

- Server components import `@/theme` (no client boundary); client components
  that need the runtime flags import `@/theme/ThemeProvider`.
- Nothing outside `theme/` should hardcode a hex value — including CSS, which
  reaches tokens through Tailwind's `theme()` function.
- Section rhythm, tone and container width are handled by
  `<Section tone="light | white | tint | dark | deep">`; headings by
  `<SectionHeading eyebrow title lead tone />`.

## Motion

- Shared variants live in `src/lib/motion.js`, built from the theme's motion
  tokens — use `<Reveal>` / `<RevealGroup>` + `<RevealItem>` rather than
  hand-rolling `whileInView`.
- `ThemeProvider` sets `reducedMotion="user"`, so the OS "reduce motion"
  setting suppresses transform animations site-wide; `globals.css` does the same
  for CSS animations, and the preloader skips itself entirely.
- The WebGL hero is code-split and client-only
  (`components/three/LazyHeroScene.jsx`) with a gradient fallback, so it never
  blocks first paint and is absent from the server bundle.

## Accessibility notes

- Skip-to-content link, visible focus rings, `aria-current` on the active nav
  item, labelled form controls, and `aria-hidden` on every decorative layer.
- The 3D canvas, grid overlays and glow blobs are all decorative and hidden from
  assistive technology.
- Icon colours on tinted chips are chosen by luminance (`readableOn` in
  `src/lib/utils.js`) to hold contrast.
